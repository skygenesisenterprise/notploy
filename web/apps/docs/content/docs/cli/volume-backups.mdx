Back up Docker volumes on a schedule and download the resulting archives.

`notploy volume-backups` exposes **6 commands**. They map one-to-one onto the `volume-backups.*` API operations, so anything reachable from the dashboard is reachable from here.

<Callout>
	Run `notploy volume-backups --help` to list these commands in your terminal, or
	`notploy volume-backups <command> --help` for a single command.
</Callout>

## Commands

### `notploy volume-backups create`

Calls `POST /api/trpc/volumeBackups.create`.

```bash
notploy volume-backups create --name <value> --volumeName <value> --prefix <value> --cronExpression <value> --destinationId <value> [options]
```

| Option | Type | Required | Allowed values |
| --- | --- | --- | --- |
| `--name <value>` | string | Yes | — |
| `--volumeName <value>` | string | Yes | — |
| `--prefix <value>` | string | Yes | — |
| `--serviceType <value>` | string | No | `application`, `postgres`, `mysql`, `mariadb`, `mongo`, `redis`, `compose`, `libsql` |
| `--appName <value>` | string | No | — |
| `--serviceName <value>` | string | No | — |
| `--turnOff [boolean]` | boolean | No | — |
| `--no-turnOff` | boolean | No | — |
| `--cronExpression <value>` | string | Yes | — |
| `--keepLatestCount <value>` | number | No | — |
| `--enabled [boolean]` | boolean | No | — |
| `--no-enabled` | boolean | No | — |
| `--applicationId <value>` | string | No | — |
| `--postgresId <value>` | string | No | — |
