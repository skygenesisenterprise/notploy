Bind mounts and named volumes attached to applications and Compose services.

`notploy mounts` exposes **6 commands**. They map one-to-one onto the `mounts.*` API operations, so anything reachable from the dashboard is reachable from here.

<Callout>
	Run `notploy mounts --help` to list these commands in your terminal, or
	`notploy mounts <command> --help` for a single command.
</Callout>

## Commands

### `notploy mounts all-named-by-application-id`

Calls `GET /api/trpc/mounts.allNamedByApplicationId`.

```bash
notploy mounts all-named-by-application-id --applicationId <applicationId>
```

| Option | Type | Required | Allowed values |
| --- | --- | --- | --- |
| `--applicationId <value>` | string | Yes | — |

### `notploy mounts create`

Calls `POST /api/trpc/mounts.create`.

```bash
notploy mounts create --type <type> --mountPath <mountPath> --serviceId <serviceId> [options]
```

| Option | Type | Required | Allowed values |
| --- | --- | --- | --- |
| `--type <value>` | string | Yes | `bind`, `volume`, `file` |
| `--hostPath <value>` | string | No | — |
| `--volumeName <value>` | string | No | — |
| `--content <value>` | string | No | — |
| `--mountPath <value>` | string | Yes | — |
| `--filePath <value>` | string | No | — |
| `--serviceType <value>` | string | No | `application`, `postgres`, `mysql`, `mariadb`, `mongo`, `redis`, `compose`, `libsql` |
| `--serviceId <value>` | string | Yes | — |
