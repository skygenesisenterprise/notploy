S3-compatible storage destinations that backups are uploaded to.

`notploy destination` exposes **6 commands**. They map one-to-one onto the `destination.*` API operations, so anything reachable from the dashboard is reachable from here.

<Callout>
	Run `notploy destination --help` to list these commands in your terminal, or
	`notploy destination <command> --help` for a single command.
</Callout>

## Commands

### `notploy destination all`

Calls `GET /api/trpc/destination.all`.

```bash
notploy destination all
```

### `notploy destination create`

Calls `POST /api/trpc/destination.create`.

```bash
notploy destination create --name <name> --provider <provider> --accessKey <accessKey> --bucket <bucket> --region <region> --endpoint <endpoint> --secretAccessKey <secretAccessKey> --additionalFlags <additionalFlags> [options]
```

| Option | Type | Required | Allowed values |
| --- | --- | --- | --- |
| `--name <value>` | string | Yes | — |
| `--provider <value>` | string | Yes | — |
| `--accessKey <value>` | string | Yes | — |
| `--bucket <value>` | string | Yes | — |
| `--region <value>` | string | Yes | — |
| `--endpoint <value>` | string | Yes | — |
| `--secretAccessKey <value>` | string | Yes | — |
| `--additionalFlags <value>` | string | Yes | — |
