Scheduled and manual backups for databases, Compose services and the web server.

`notploy backup` exposes **12 commands**. They map one-to-one onto the `backup.*` API operations, so anything reachable from the dashboard is reachable from here.

<Callout>
	Run `notploy backup --help` to list these commands in your terminal, or
	`notploy backup <command> --help` for a single command.
</Callout>

## Commands

### `notploy backup create`

Calls `POST /api/trpc/backup.create`.

```bash
notploy backup create --schedule <schedule> --prefix <prefix> --destinationId <destinationId> --database <database> --databaseType <databaseType> [options]
```

| Option | Type | Required | Allowed values |
| --- | --- | --- | --- |
| `--schedule <value>` | string | Yes | — |
| `--enabled` | boolean | No | — |
| `--prefix <value>` | string | Yes | — |
| `--destinationId <value>` | string | Yes | — |
| `--keepLatestCount <value>` | number | No | — |
| `--database <value>` | string | Yes | — |
| `--mariadbId <value>` | string | No | — |
| `--mysqlId <value>` | string | No | — |
| `--postgresId <value>` | string | No | — |
| `--mongoId <value>` | string | No | — |
| `--libsqlId <value>` | string | No | — |
| `--databaseType <value>` | string | Yes | `postgres`, `mariadb`, `mysql`, `mongo`, `web-server`, `libsql` |
| `--userId <value>` | string | No | — |
| `--backupType <value>` | string | No | `database`, `compose` |
| `--composeId <value>` | string | No | — |
| `--serviceName <value>` | string | No | — |
| `--includeEncryptionKey` | boolean | No | — |
| `--metadata <value>` | string | No | — |
