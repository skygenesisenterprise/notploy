## Concepts before endpoints

All interfaces speak the same model described in [Core concepts](/docs/core/concepts): organizations, projects, environments, services and deployments. The API is the source of truth; the CLI, SDK and MCP server are thin clients over it.

## Authentication

Programmatic access uses **API keys** (or tokens) scoped to a user or organization. The CLI and SDK authenticate with a key you generate in the dashboard. See [API keys](/docs/core/security/api-keys) for creation, scope and handling.

## Automation patterns

- **Deploy from CI** — trigger a deployment when a branch is pushed, either through the provider webhook ([auto-deploy](/docs/core/auto-deploy)) or by calling the API from your pipeline.
- **Preview environments** — create temporary deployments per pull request. See [Preview deployments](/docs/core/applications/preview-deployments).
- **Infrastructure as code** — reconcile projects and services with the SDK or CLI.

## Status of interfaces

The API and CLI are the most stable interfaces. The SDK mirrors the API. The MCP server and VS Code extension are integration surfaces whose contracts may evolve faster — check each page for its current status.
