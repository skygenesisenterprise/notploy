**Notploy** is an open-source platform that gives you a web control plane for deploying and operating applications, databases and Docker Compose stacks on servers you control. You connect a machine, and Notploy builds, ships, routes and monitors your workloads using standard primitives — **Docker**, **Docker Swarm** and **Traefik**.

It brings the developer experience of a managed Platform-as-a-Service to your own infrastructure: `git push`, a build, a running container behind a domain with TLS — without handing over your servers, your data or your bill.

## What problem does it solve?

Deploying a real application normally means stitching together a build pipeline, an image registry, a reverse proxy, TLS certificates, DNS records, databases, backups and monitoring. Each of those is a separate tool with its own configuration, and keeping them consistent across environments is where most of the work — and most of the outages — come from.

Notploy consolidates that surface into one control plane:

- **One model** for applications, databases and Compose stacks that share projects, environments, secrets, domains and backups.
- **One place** to see deployment status, logs, resource usage and failures.
- **A consistent contract** — the same deployment engine whether you run on the local server, on remote servers over SSH, or on a Swarm cluster.
- **Interfaces for automation** — an API, CLI, TypeScript SDK, MCP server and VS Code extension so deployments fit into existing pipelines instead of replacing them.

## Where does it run?

Notploy is designed around a single, explicit place to run things: your **server**. That can be:

- the **same machine** where the Notploy control plane is installed (the default — start here),
- **independent remote servers** reached over SSH, or
- **nodes of a Docker Swarm cluster** for replicated workloads.

See [Deployment Options](/docs/core/deployment-options) for how to choose, and [Architecture](/docs/core/architecture) for how the pieces fit together.

## What can you do with it?

- **Deploy** from Git providers (GitHub, GitLab, Bitbucket, Gitea), any Git URL, a container image or a raw Compose file, using Docker, Nixpacks, Railpack or buildpacks.
- **Operate** PostgreSQL, MySQL, MariaDB, MongoDB and Redis with scheduled backups.
- **Route** traffic through Traefik with managed domains and automatic TLS.
- **Scale** from one server to remote servers or a Swarm cluster.
- **Automate** everything through the API, CLI, SDK and MCP server.

The full list lives in [Capabilities](/docs/core/features).

## Which edition am I reading about?

Notploy ships in several editions that share one deployment engine. The documentation marks edition-specific behavior explicitly; when a page has no label, it applies to **Self-Hosted** and **Cloud** alike.
