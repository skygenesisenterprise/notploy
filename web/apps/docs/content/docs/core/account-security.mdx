Every sign-in starts with your password. Two-factor authentication (2FA) adds a second proof on top of it — a time-based code from an authenticator app, or a security key (WebAuthn). Both methods can be registered on the same account, and either one completes the second step.

## Two-Factor Authentication (2FA)

### Enabling 2FA

1. Go to **Settings → Profile**.
2. In the **2FA** section, click enable and scan the QR code with your authenticator app.
3. Confirm with a generated code, and store the backup codes somewhere safe — they are the recovery path if you lose the authenticator.

Once enabled, password sign-ins require the current code from your app.

## Security keys (WebAuthn)

A security key is a second factor based on WebAuthn. It lives in the authenticator itself: a hardware key such as a YubiKey, the platform authenticator (Touch ID, Face ID, Windows Hello), or a key stored in a password manager such as Bitwarden, 1Password, or iCloud Keychain. The credential never leaves the authenticator and is bound to your Notploy domain, so it is resistant to phishing.

A security key never replaces the password: it is only accepted after the password step.

### Registering a security key

1. Enable 2FA first — the security key is offered as a second factor.
2. Go to **Settings → Profile → Security** and open **Security key** in the 2FA card.
3. Give the key a recognizable name (e.g. `YubiKey`, `Bitwarden vault`) and follow your browser's prompt.
4. On the next sign-in, enter your password, then choose **Use a security key** instead of typing a code.

You can register up to ten keys and remove them individually at any time. Removing a key leaves the authenticator codes in place.

<Callout type="info">
  Register a second key (or keep your backup codes) so losing one device doesn't lock you out. Backup codes remain usable when no security key is available.
</Callout>

## Choosing a second factor

- **Authenticator codes** work anywhere, with no extra hardware, but a code can be phished.
- **Security keys** are phishing-resistant and require nothing to type; the browser and device must support WebAuthn (HTTPS or localhost).
- You can keep both: sign in with the key when it is available, and fall back to a code or a backup code otherwise.

<Callout type="info">
  Organization owners on Notploy Cloud and self-hosted instances with SSO can additionally enforce sign-in through their identity provider — see the SSO documentation.
</Callout>
