The reference section is the lookup layer: precise, structured facts you consult rather than read end to end. Concepts and procedures live in the other sections; this one answers "what are the exact options, values and boundaries?".

<Callout type="info" title="Reference pages mirror the implementation">
Reference content is validated against the code and the running product. Where a value varies
by edition or version, the page says so. If a reference page and the product disagree, treat
that as a documentation bug — see [Contributing](/docs/core/develop/contributing).
</Callout>

## How to read status labels

Across the documentation, capabilities are labelled:

- **Available** — implemented and verified in the current release.
- **Experimental** — implemented but incomplete or subject to change.
- **Planned** — on the roadmap; not available.
- **Unsupported** — out of scope or not supported in the relevant edition.

The [feature matrix](/docs/core/reference/feature-matrix) aggregates these labels by edition.
