Where the [Applications](/docs/core/applications) section is about what you deploy, this section is about **where and how it runs**. Notploy is built on standard infrastructure components — Docker, Docker Swarm and Traefik — and this section documents how Notploy manages them and how you configure the surrounding services.

## Networking and routing

- **[Traefik](/docs/core/traefik)** — the reverse proxy that routes traffic to services and terminates TLS.
- **[DNS providers](/docs/core/dns-providers)** — automate DNS records (Cloudflare, Route53).
- **[Certificates](/docs/core/certificates)** — automatic and custom TLS certificate lifecycle.

## Storage

- **[Registries](/docs/core/registry)** — push and pull images for remote servers and clusters.
- **[Object storage (S3)](/docs/core/s3-destinations)** — destinations for backups.
- **[Backups](/docs/core/backups)** and **[volume backups](/docs/core/volume-backups)** — protect data and restore it.

## Secrets and integrations

- **[Secrets providers](/docs/core/secrets-providers)** — read secrets from external vaults.
- **[Notifications](/docs/core/overview)** — delivery channels for deployments and alerts.

## How each infrastructure guide is structured

Because infrastructure mistakes are expensive, each guide in this section covers, where relevant:

- **Purpose** — what the component is for and when to use it.
- **Architecture** — how it fits into Notploy and what it depends on.
- **Prerequisites** — resources, permissions, ports and protocols.
- **Configuration** — how to set it up.
- **Verification** — how to confirm it works.
- **Troubleshooting and recovery** — common failures and their consequences.
