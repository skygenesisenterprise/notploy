This page is an inventory of what Notploy does, grouped by intent rather than by screen. Each capability links to the page that explains it. Features that are experimental or edition-specific are labelled where they appear in the detailed pages.

## Deploy

- **Applications** built from a Git provider, any Git URL, a container image, or an uploaded archive.
- **Build types**: Dockerfile, Nixpacks, Railpack, Heroku/Paketo buildpacks, or a prebuilt image (no build).
- **Docker Compose** stacks from a repository or a raw `docker-compose.yml`, edited in-app.
- **Blueprints** from the [Notploy Templates gallery](https://templates.notploy.com) for one-click starting points.
- **Databases**: PostgreSQL, MySQL, MariaDB, MongoDB and Redis.
- **[Preview deployments](/docs/core/applications/preview-deployments)** for pull requests and branches.
- **[Auto-deploy](/docs/core/auto-deploy)** from Git webhooks and CI.

→ [Applications & deployment](/docs/core/applications)

## Operate

- **Domains and TLS** with automatic Let's Encrypt certificates and a generated-domain option for quick tests.
- **Environment variables and secrets** at project, environment and service scope, plus external [secret managers](/docs/core/secrets-providers).
- **Volumes and mounts** for persistent data, with [volume backups](/docs/core/volume-backups) for Docker named volumes.
- **Scheduled backups** for databases and volumes to S3-compatible storage, with [restore](/docs/core/databases/restore).
- **Scheduled jobs** (cron) against your services.
- **Logs and resource monitoring** per service and per server.
- **Notifications** to Slack, Discord, Telegram, Teams, email and others.
- **[Rollbacks](/docs/core/applications/rollbacks)** to a previous deployment.

→ [Operate & administer](/docs/core/administration)

## Automate

- **REST API** covering the management model.
- **CLI** for terminal-driven workflows.
- **TypeScript SDK** for programmatic use.
- **MCP server** for AI-assisted tooling.
- **VS Code extension** for editor integration.
- **CI/CD** integration for deploying from your pipelines.

→ [Develop & integrate](/docs/core/develop) · [API reference](/docs/api)

## Scale

- **Local server** (single machine) as the default topology.
- **Remote deployment servers** over SSH for isolation and distribution.
- **Dedicated build servers** to offload builds and push to a registry.
- **Docker Swarm cluster** to replicate the same application across nodes with load balancing.

→ [Deployment options](/docs/core/deployment-options)

## Govern

- **Organizations, members and roles**, with [custom roles](/docs/core/enterprise/custom-roles) in Enterprise.
- **SSO** (OIDC / SAML) and **SCIM provisioning** in Enterprise.
- **Audit logs** in Enterprise.
- **Whitelabeling** in Enterprise Self-Hosted.
- **Multi-tenancy** for running several isolated organizations.

→ [Permissions](/docs/core/permissions) · [Enterprise](/docs/core/enterprise)
