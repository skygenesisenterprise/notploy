This section covers everything about turning a source into a running service: choosing where code comes from, how it is built, how it is configured and exposed, and how the deployment lifecycle behaves.

A **service** in Notploy is one of three kinds — an **Application**, a **Database**, or a **Docker Compose** stack — and all three share the same operational surface. This section is organized around that surface.

## Projects, environments and services

A [project](/docs/core/concepts#project) groups related services; an [environment](/docs/core/concepts#environment) is the deployment context inside it (for example `production` and `staging`); a [service](/docs/core/concepts#service) is what actually runs. Configuration resolves from broad to specific — project, then environment, then service.

## The deployment lifecycle

Every service moves through the same lifecycle:

1. **Source** is fetched (Git clone, image pull, or upload).
2. **Build** produces an image according to the service's [build type](/docs/core/applications/build-type).
3. **Release** starts the new container as a Swarm service; the old one is drained.
4. **Route** — Traefik exposes the service on its [domains](/docs/core/domains).
5. **Record** — the [deployment](/docs/core/concepts#deployment) is stored with its logs and status.

Health checks, logs, [rollbacks](/docs/core/applications/rollbacks) and [zero-downtime](/docs/core/applications/zero-downtime) behavior all attach to this lifecycle.

## What you can configure on a service

All service types share these tabs, with the same meaning everywhere:

| Tab | Purpose |
| --- | --- |
| **General** | Source, build configuration and lifecycle actions (deploy, stop, delete). |
| **Environment** | Variables and secrets, addressed by scope. |
| **Domains** | Hostnames, ports and TLS. |
| **Deployments** | History, logs, cancel and rollback. |
| **Logs** | Real-time runtime output. |
| **Monitoring** | CPU, memory, disk and network. |
| **Advanced** | Commands, resources, volumes, ports, Traefik and cluster settings. |

Learn this surface once on an Application, and it applies to Databases and Compose unchanged.
